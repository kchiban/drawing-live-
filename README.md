# 🎨 Collaborative Drawing Board

A real-time collaborative drawing web application where multiple users can draw together simultaneously. Built with Node.js, Express, Socket.io, and HTML5 Canvas.

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](https://opensource.org/licenses/MIT)
[![Node.js Version](https://img.shields.io/badge/node-%3E%3D14.0.0-brightgreen)](https://nodejs.org/)
[![Socket.io](https://img.shields.io/badge/Socket.io-4.6%2B-blue)](https://socket.io/)

## ✨ Features

### Core Functionality
- 🎨 **Real-Time Canvas Drawing** - All users see drawings instantly
- 👥 **Multi-User Support** - Up to hundreds of concurrent users
- 🎯 **Cursor Labels** - See other users' names on their cursors
- 🌈 **Color Picker** - Choose any color for your brush
- 🖌️ **Adjustable Brush Size** - Fine control from 1-50px
- 💬 **Built-in Chat** - Communicate while drawing
- 👤 **User Identification** - Optional names or anonymous drawing

### Administration & Monitoring
- 📊 **Statistics Dashboard** - Real-time monitoring of users and stats
- 🔍 **IP Tracking** - Track all connected IP addresses
- 🚫 **IP Banning System** - Ban users by IP address
- 👢 **User Kick Function** - Disconnect specific users
- ⚡ **Real-Time Stats** - Online count, join times, history size
- 📈 **Performance Metrics** - Server uptime and memory usage

### Technical Features
- ⚡ **Low Latency** - WebSocket-based real-time communication
- 📱 **Responsive Design** - Works on desktop and tablet
- 🎮 **Drawing History** - New users see previous drawings
- 🔄 **Auto-Refresh Dashboard** - Stats update every 5 seconds
- 📦 **Production Ready** - Redis support for scaling
- 🐳 **Docker Support** - Easy containerized deployment

## 🚀 Quick Start

### Prerequisites
- Node.js 14+ 
- npm 6+
- Modern web browser (Chrome, Firefox, Safari, Edge)

### Installation

```bash
# 1. Clone the repository
git clone <repository-url>
cd collaborative-drawing-board

# 2. Install dependencies
npm install

# 3. Create environment file
cp .env.example .env

# 4. Start the server
npm start

# 5. Open in browser
# http://localhost:3000
```

### Development Mode

```bash
npm run dev
```

This uses `nodemon` to auto-restart on file changes.

## 🎮 How to Use

### Drawing

1. **Enter your name** (optional - leave blank for anonymous)
2. **Click "Start Drawing"** to join
3. **Select color** with the color picker
4. **Adjust brush size** with the slider
5. **Draw on the canvas** - your brush moves in real-time
6. **See other users** drawing simultaneously
7. **Click their name** on their cursor to identify them
8. **Use chat** to communicate while drawing
9. **Clear canvas** when done

### Admin Dashboard

1. Navigate to **http://localhost:3000/stats.html**
2. View all connected users in real-time
3. See IP addresses and join times
4. Ban users by clicking the **Ban IP** button
5. Kick individual users with the **Kick** button
6. Monitor drawing history size
7. Toggle auto-refresh (default: 5 seconds)

## 🔧 Configuration

### Environment Variables

```env
# Server
PORT=3000
NODE_ENV=development

# Socket.io
MAX_HISTORY_SIZE=5000
SOCKET_TIMEOUT=60000

# IP & Ban
IP_TRACKING_ENABLED=true
BAN_PERSISTENCE=false

# Features
ENABLE_CHAT=true
ENABLE_STATS=true
ENABLE_DRAWING_HISTORY=true

# Redis (for production scaling)
REDIS_ENABLED=false
REDIS_HOST=localhost
REDIS_PORT=6379
```

## 📊 API Endpoints

### REST API

```
GET  /api/stats              # Get all statistics
POST /api/ban-ip             # Ban an IP address
POST /api/unban-ip           # Unban an IP address
POST /api/kick-user          # Disconnect a user
GET  /api/health             # Health check
```

### Socket.io Events

**Client → Server:**
- `user_join` - Join the drawing session
- `draw` - Send draw command
- `cursor_move` - Update cursor position
- `clear_canvas` - Clear the canvas
- `send_message` - Send chat message

**Server → Client:**
- `welcome` - Initial connection data
- `user_joined` - User join notification
- `user_left` - User disconnect notification
- `draw` - Remote draw command
- `user_cursor` - Cursor position update
- `receive_message` - Chat message
- `canvas_cleared` - Canvas clear notification

## 📈 Performance

### Benchmarks
- User join: <100ms
- Draw broadcast: <50ms
- Supports 100+ concurrent users
- Tested with 50 simultaneous connections

### Optimization Tips
- Limit drawing history to ~5000 events
- Clear canvas periodically to reset history
- Use Redis for multi-server deployment
- Enable compression for production
- Monitor memory usage on long sessions

## 🛠️ Troubleshooting

### Canvas not displaying
- Check browser console for errors
- Ensure JavaScript is enabled
- Try clearing browser cache

### Drawing not syncing
- Verify WebSocket connection (Dev Tools → Network → WS)
- Check that server is running
- Look for errors in server logs

### Users not visible
- Refresh the page
- Check browser console
- Verify Socket.io is loading

### IP tracking not working
- Review server logs
- Check if behind reverse proxy
- Verify x-forwarded-for header
